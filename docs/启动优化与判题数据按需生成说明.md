# 启动优化与判题数据按需生成说明

> 相关分支：`feature/middleware-http-gateway`
> 更新日期：2026-09-23

本文记录客户端/服务端（出题端）在「HTTP 中间件网关」架构下的一次性能与健壮性修复：
启动加速、判题数据按需生成、中文生成器名编码修复，以及内存泄漏排查结论。

---

## 1. 背景

数据访问已统一收口到 HTTP 中间件网关（`middlewareUrl`），客户端与出题端不再直连 MySQL / LSM。
每次客户端启动会调用 `oj_mysql_sync_problems()`，从网关拉取题目、标程与数据生成器源码并物化到本地目录，
用于判题时读取测试数据。

## 2. 问题：启动过慢

`client\bin\Debug\startup.log` 显示一次启动耗时约 **50 秒**：

```
[12:44:28] OnStartup 开始
[12:45:19] 服务初始化完成, MySqlEnabled=True   ← 约 51s，其中约 42s 在重新生成数据
```

### 根因

1. 题目 111 绑定了一个**中文名生成器「测64」**（另一个是 `test`）。
2. `mysql_dao.cpp` 的同步逻辑使用 **ANSI 文件 API**（`CreateDirectoryA` / `FindFirstFileA` / `CreateFileA`）
   处理从 JSON 取得的 UTF-8 中文名，编码不匹配导致该生成器目录无法正确创建 → `RegenerateProblemData` 失败。
3. 失败后 `.genhash` 缓存标记**永远写不上**（只有全部生成成功才写标记），于是每次启动都把
   标程 + 所有生成器重新 g++ 编译、跑 20+ 个子进程。
4. 失败被静默吞掉：函数末尾 `err.clear(); return true;` 清掉了错误，C# 端也 `catch {}` 忽略返回值。

## 3. 修复内容

### 3.1 中文生成器名编码修复（客户端）

- 生成器本地目录从「原始名」改为 ASCII 的 `g{id}`（`GenInfo` 新增 `dirName` 字段；
  `seedBase` 仍按原始名哈希，与网关 `bind_generator` 公式一致）。
- 数据生成失败不再吞掉，`middleware_sync_problems` 直接 `return false` 并携带错误信息。

### 3.2 初始化不再生成数据（懒加载）

- `middleware_sync_problems` 只物化源码与元数据：
  - `gen.cpp`、`desc.txt`
  - 新增 `genmeta.txt`（`{count, seedBase, name}`，供判题时按需生成使用）
- 删除了同步阶段的 hash 校验 + `RegenerateProblemData` 编译/运行。

### 3.3 判题时按需生成，且不计入判题时间

- 新增 `oj::ensure_problem_data(problem_id, problem_dir, err)`（`mysql_dao.cpp`）：
  枚举各生成器目录（含 `genmeta.txt`），读取本地 `gen.cpp` + `genmeta.txt` + `std.cpp`，
  重新计算 hash 与 `.genhash` 及 `.in/.out` 完整性比对，仅过期或缺失时才 `RegenerateProblemData`。
  - 使用静态互斥锁 `g_gen_mtx` 防止同题并发判题时重复生成。
- `api.cpp` 的 `do_judge` 在**编译用户代码、`run_tests` 之前**调用 `ensure_problem_data`，
  因此生成耗时发生在每个测试点计时（`run_one` 的 `QueryPerformanceCounter`）之前，
  不进入 `totalMs`，不会造成 TLE。
- 导出 C API `oj_ensure_problem_data(int problem_id)`（`ojcore.h`）。

### 3.4 中文生成器名编码修复（出题端 authorcore）

- `authorcore/gen.cpp` 新增 `safeName()`：非 ASCII 名字映射为 `g_` + FNV-1a64(名字 UTF-8 字节)，
  `genDir` / `genExePath` / `test*` 路径全部经过它。
- `validGenName` 放宽为允许非 ASCII，仍拒绝路径分隔符、Windows 非法字符、保留名。
- `AuthorClient.cs` 新增 `SafeGenName()`（与 C++ 同算法），`LoadFromMySql` 物化目录时改用该名字，
  保证 C# 物化目录与 C++ 编译/运行目录一致。

## 4. 效果

| 阶段 | 改动前 | 改动后 |
|------|--------|--------|
| 客户端启动同步 | ~42s（每次重新编译+生成） | ~6-7s（仅 HTTP 拉取 + 物化源码） |
| 首次判题某题 | 数据已预生成 | 一次性生成（~50s，主要是 g++ 子进程开销） |
| 再次判题同题 | — | 命中缓存（~8ms） |
| 判题计时 | 生成在前 | 生成在计时之外，不影响 TLE |

## 6. 内存泄漏排查结论

- **客户端 `ojcore.dll`**：无泄漏。仅 `dup()` 一处 `malloc`，由 `oj_free_string` 配对释放；
  `run_one` / `compile_cpp` / `RunRedirect` 的所有 `HANDLE` 均 `CloseHandle`，`hJob` 正确关闭。
- **出题端 `authorcore.dll`**：无泄漏。同样 `dup()` / `ac_free_string` 配对，句柄全部关闭。
- **中间层网关（远端）**：本机无 SSH 凭据，未直接检查；从接口表现看无异常。
  如需排查：`for i in $(seq 1 20); do ps -o rss=,etime= -p $(pgrep -f mq_middleware); sleep 30; done`

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build.ps1 -Core

```
