# 判题数据：二进制可执行文件代替源码

## 目标

判题数据不再依赖客户端本地 `g++` 编译源码，而是：

1. **出题端**在发布/编译时把标程与生成器编译成 Windows exe，上传到数据库；
2. **客户端**从数据库拉取二进制 exe，直接运行生成 `.in` / `.out`。

数据生成仍发生在客户端本地（数据库只存可执行文件，不存上 GB 的测试数据）。

### 1. 数据库迁移

```sql
ALTER TABLE problems   ADD COLUMN std_exe LONGBLOB AFTER std_code;
ALTER TABLE problems   ADD COLUMN spj_code MEDIUMTEXT AFTER std_exe;
ALTER TABLE problems   ADD COLUMN spj_exe  LONGBLOB  AFTER spj_code;
ALTER TABLE generators ADD COLUMN exe     LONGBLOB AFTER code;
```

### 2. 接口

- `POST /api/problem/upsert`：请求体新增 `stdExe` / `spjCode` / `spjExe`（base64，可空），base64 解码后分别写入 `problems.std_exe` / `problems.spj_code` / `problems.spj_exe`。
- `GET  /api/problem?id=`：响应新增 `stdExe`（`problems.std_exe` 的 base64）、`spjCode`（`problems.spj_code`）、`spjExe`（`problems.spj_exe` 的 base64）；`generators[]` 每项新增 `exe`（`generators.exe` 的 base64）。
- `POST /api/generator/exe`（新增）：请求体 `{ "id": 1, "exe": "<base64>" }`，解码写入 `generators.exe`。返回 `{"ok":true}` 或 `{"ok":false,"error":"..."}`。

> 建议中间层把 `std_exe` / `exe` 沿用源码的 AES 加密方式落库（避免明文 exe 入库），对外接口仍以 base64 明文传输（客户端/出题端已按明文 base64 处理）。

## 兼容性

- 数据库尚无二进制（老题目、未重新发布）时，`stdExe` / `exe` / `spjExe` 为空，客户端自动回退到旧路径（拉取源码 + 本地 `g++` 编译 + 运行）。
- 出题端重新「发布」题目会更新 `std_exe` / `spj_exe`；生成器「编译」会更新 `generators.exe`。

## 特殊判题（SPJ）

- 出题端在「特殊判题 (SPJ)」页编写 `spj.cpp` 并编译，发布时随题目一起上传到数据库。
- 客户端判题时若该题存在 `spj.cpp` / `spj.exe`，则对每个测试点运行：
  `spj.exe <用户输出> <标准输出> <输入>`
  退出码 0 = 通过（AC）；非 0 = WA（detail 记 `special judge 未通过`）；超时 = TLE；启动失败 = SE。
- 留空 `spj.cpp` 则不启用 SPJ，回退到普通文本比对。
